# GL Guardian - Automated Audit

Enterprise audit investigation platform powered by a multi-agent AI crew. It automates fraud
detection and risk assessment through an adversarial debate framework (Challenger vs. Defender),
with mandatory human-in-the-loop review and an immutable, hash-chained audit log.

## How it works

```
CASE INTAKE            EVIDENCE COLLECTION        DEBATE + VERIFICATION           DECISION
CSV upload → rules  →  Supervisor + Evidence   →  Challenger ↔ Defender (≤2   →  Confidence gate:
pre-filter                agent (RAG + live         rounds) → Adjudicator          ≥0.90 verified/low
                           APIs) → citations         verdict → Verifier QA          → auto-clear
                                                                                     0.70-0.90 → review
                                                                                     <0.70 → escalate
                                                                                          ↓
                                                                              REPORT + AUDIT
                                                                              MD/HTML/PDF report,
                                                                              immutable audit log
```

**Agent roles**: Supervisor (orchestrator) · Evidence agent (RAG + live APIs) · Challenger
(risk case) · Defender (legitimacy case) · Adjudicator (verdict) · Verifier (grounding QA).

## Tech stack

**Backend** — FastAPI, PostgreSQL + pgvector (RAG), SQLAlchemy/Alembic, Redis + Celery (async
tasks), EventStoreDB (immutable audit trail), LangGraph + LangChain (agent orchestration).

**LLM providers** — Anthropic Claude, Groq, OpenAI, Google Gemini, DeepSeek, selectable per
environment with automatic fallback (`Backend/app/llm/`).

**Observability** — Prometheus metrics at `GET /metrics` (HTTP + LLM cost/latency/token +
investigation pipeline metrics) and optional LangSmith tracing for every LangGraph/LLM call.

**Frontend** — Next.js 15 App Router, React 19, TypeScript, Tailwind CSS, TanStack Query/Table,
React Flow (agent workflow visualization), Recharts.

## Getting started

### Backend

```bash
cd Backend
python -m venv .venv && .venv/Scripts/activate   # or source .venv/bin/activate on macOS/Linux
pip install -r requirements.txt
cp .env.example .env      # fill in DATABASE_URL, LLM provider keys, etc.
uvicorn app.main:app --reload
```

API docs: `http://localhost:8000/docs` · Health: `http://localhost:8000/health` · Metrics:
`http://localhost:8000/metrics`

See [Backend/QUICKSTART.md](Backend/QUICKSTART.md) and [Backend/PREREQUISITES.md](Backend/PREREQUISITES.md)
for the full local stack (Postgres, Redis, EventStoreDB via `docker-compose.local-infra.yml`).

### Frontend

```bash
cd Ui
pnpm install
cp .env.example .env      # point NEXT_PUBLIC_API_URL at the backend
pnpm dev
```

Open `http://localhost:3000/dashboard`.

## Experiments and Evaluation

The first reproducible benchmark is now checked into
[`Backend/experiments`](Backend/experiments/README.md). The result below was
generated by `python scripts/evaluate_experiments.py` from `Backend/`; the JSON
artifact is [`Backend/experiments/results/latest.json`](Backend/experiments/results/latest.json).

### Dataset and split

The available benchmark is the bundled **synthetic** ledger of 1,000
transactions (`sample_gl_1000.csv`). It contains 937 rows whose `risk_hint` is
not `normal` and 63 `normal` rows. This is an anomaly-screening proxy, **not an
adjudicated fraud dataset**. Results must therefore not be represented as
real-world fraud-detection accuracy.

The script assigns rows by SHA-256 of a fixed seed (`20260728`) and transaction
ID: 763 development rows and 237 held-out evaluation rows. The evaluation set
contains 222 proxy-positive and 15 proxy-negative rows. `risk_hint` is used only
by the scorer and is never passed to a method. No model is trained in this
experiment.

### Measured results

| Method | Accuracy | Precision | Recall | F1 | Groundedness | Citation correctness | Cost / investigation | Avg. latency |
|---|---:|---:|---:|---:|---:|---:|---:|---:|
| Rule baseline | 0.9367 | 0.9367 | 1.0000 | 0.9673 | N/A | N/A | $0.00 | <0.001 ms |
| Single LLM | Not run | Not run | Not run | Not run | Not run | Not run | Not run | Not run |
| Multi-agent system | Not run | Not run | Not run | Not run | Not run | Not run | Not run | Not run |

The high baseline F1 is not evidence of a strong detector: the held-out set is
93.7% positive, the baseline flagged all 237 cases, and its specificity was
**0.0000** (`TP=222, FP=15, FN=0, TN=0`). Reporting the confusion matrix prevents
the class imbalance from being hidden by a headline score.

### Agentic evaluation, groundedness, and citations

The runner accepts complete prediction CSVs for single-LLM, multi-agent, and
ablation runs. It fails if any held-out transaction is missing, preventing
selective reporting. Optional per-case fields capture independently judged
groundedness, citation correctness, measured cost, and end-to-end latency. The
exact input contract and command are documented in
[`Backend/experiments/README.md`](Backend/experiments/README.md).

No agentic figures are published yet because this repository does not contain a
complete recorded run on the fixed split or the provider credentials and live
services needed to create one. Telemetry-derived dashboard proxies are not used
as benchmark truth. Publishing `Not run` is intentional and preferable to
inventing values.

### Ablations and failure cases

Ablations use one prediction file per variant (for example, no Challenger, no
Verifier, or no RAG) and the identical held-out IDs and scorer. None have been
run yet. The current baseline's failures are all 15 proxy-negative rows, which
it falsely flags; the first 10 IDs are preserved in the generated JSON. This
exposes two immediate dataset/method failures: severe label imbalance and rules
that do not discriminate the negative class. The next credible experiment must
add independently adjudicated positive and negative cases, then execute the
single-LLM, full crew, and ablations on the frozen split.

### Reproduce

```bash
cd Backend
python scripts/evaluate_experiments.py
python -m pytest tests/test_experiment_evaluation.py -q
```

Do not hand-edit the generated result or infer missing values.
